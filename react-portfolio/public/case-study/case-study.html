01 The Challenge & Context

Qhakaza Art Collective required a modern digital platform to handle three distinct, sensitive user workflows:

  • Artists: Needed an intuitive dashboard to upload high-resolution artwork, manage submissions, and receive curatorial review questions without seeing other artists' works or collector data.
  • High-Net-Worth Collectors: Needed a private, invitation-only showcase to browse curated work, review artist intelligence dossiers, and submit private enquiries.
  • Curators & Administrators: Needed an internal "Command Center" to run multi-stage artwork vetting, manage team access, issue tokenized member invites, and review immutable audit logs.

The Core Engineering Challenge: A single monolithic website would create severe risks of data leakage between collectors and artists. The architecture needed to physically isolate the three audiences at the DNS/domain level while synchronizing state across a single, unified database.

02 The 3-Platform Ecosystem

Rather than building one generic site with role-toggled navigation, the team architected three specialized web applications deployed independently on Vercel:

1. Vera Platform Artist & Public

Artist workspace for uploading artwork with client-side progress bars and previews. Submissions enter a strict status machine (`Draft` → `Review` → `Question` → `Approved`). Houses the public browse showcase.

03 Architecture & Database-Level Security

Security in this ecosystem is not handled merely by hiding UI buttons. Instead, we implemented 208 Row-Level Security (RLS) rules in PostgreSQL to guarantee authorization is enforced directly at the data layer.

208 RLS Policies • Role-Based Access (Admin / Advisor / Analyst) • Immutable Audit Logs

Real-World Security Example: The platform defines three staff tiers: Admin, Advisor, and Analyst. Analysts are responsible for artwork research dossiers but are legally barred from seeing collector financial records. Rather than simply hiding the financial UI tab, the PostgreSQL RLS policy returns exactly 0 rows if an Analyst user attempts to query the collector table directly.

04 Key Engineering Contributions

As part of the Melsoft development team, my responsibilities spanned frontend implementation, backend schema integration, and end-to-end security pipelines:

Cryptographic Invitation Pipeline

Engineered secure member invite links. When staff generate an invitation, a unique cryptographically random token is generated with an automatic 14-day expiry.

The plaintext URL is displayed once to the administrator, while only a SHA-256 hashed fingerprint is persisted in the database. Staff can instantly revoke or reissue tokens if lost.

Private Media Uploads with Signed URLs

Constructed direct media upload pipelines for artists submitting high-resolution artwork images, including client-side progress bars and previews.

Assets are saved into private cloud storage buckets and accessed exclusively through time-limited private signed URLs, preventing unvetted art or hotlinking leaks.

Multi-Stage Artwork Approval State Machine

Implemented the end-to-end vetting roundtrip: an artist submits work → staff review in Command Center → curators can return the submission with specific feedback.

Artists receive the exact curator feedback in their portal and can revise and resubmit. Artwork can only be published to the public browse gallery once explicitly approved by an Admin.

AI-Assisted Delivery & Automated Testing

Leveraged AI-assisted development workflows to accelerate feature scaffolding, validate complex PostgreSQL RLS policies against edge cases, and author over 510 automated tests.

This significantly reduced development cycles and ensured zero regression across 38 interconnected pages before final client handover.
